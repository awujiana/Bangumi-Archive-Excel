# 条目类型与关系类型说明

> 结论先行：你在 Excel / 插件里看到的 `3001`、`3009`、`10`、`3004`、`3005`、`3003`、
> `11`、`99`、`1099`、`3007`、`8`、`1004`、`3002`、`4014` 等，**不是作品（条目）类型**，
> 而是 `subject-relations` 数据里的**关联关系类型**（字段 `relation_type`）。
>
> 作品/条目类型只有 `1、2、3、4、6` 五种，它们**已经全部在流水线中**。
> 关系类型属于非作品类型，不参与独立归档，也不需要加入 `ALL_TYPES`。

---

## 1. 作品（条目）类型

来源：[resources/yaml/subject_platforms.yml](../resources/yaml/subject_platforms.yml) 的
`define.type`，经 `legacy/python/yaml_loader.py::get_type_definitions()` 派生为
`TYPE_NAME_MAP / TYPE_ENGLISH_NAMES / ALL_TYPES`。

| 类型编号 | 中文名 | 英文标签 | 数据文件前缀 | 仓库子目录 | 是否作品类型 | 是否在流水线 |
|---------:|--------|----------|--------------|------------|:------------:|:------------:|
| 1 | 漫画（书籍） | Manga | `manga.` | `manga/` | 是 | 是 |
| 2 | 动画 | Anime | `anime.` | `anime/` | 是 | 是 |
| 3 | 音乐 | Music | `music.` | `music/` | 是 | 是 |
| 4 | 游戏 | Game | `game.` | `game/` | 是 | 是 |
| 6 | 三次元 | Real | `real.` | `real/` | 是 | 是 |

- 这五种就是 `ALL_TYPES`，也是 dump 文件名 `typeN_*.jsonlines` 的 `N`。
- Excel 产物名里的 `ani-bangumi-type{N}-日期.xlsx` 同样只取这五个值。
- 每个类型内部的平台/形态细分（如动画 TV/OVA/剧场版、书籍 漫画/小说）见第 3 节。

### 如何新增一个作品类型

只有 Bangumi 官方新增「顶层条目类型」时才需要改这里，步骤如下：

1. 在 `resources/yaml/subject_platforms.yml` 的 `define.type` 增加 `key: 编号`；
2. 在 `legacy/python/yaml_loader.py` 的 `_TYPE_KEY_CN_MAP / _TYPE_KEY_EN_MAP` 补充中英文名；
3. 重新生成数据仓库；`ALL_TYPES`、`TYPE_NAME_MAP`、各路径函数会自动派生。

关系类型**永远不走**这条路径。

## 3. 平台 / 分类编码（`subject.platform`）

条目类型只回答“这是漫画还是动画”，同一类型内部还会用 `platform` 再细分
（例如动画的 TV/OVA/剧场版/动态漫画）。这些编码**按 type 各自定义**，
同一个数字在不同 type 下含义完全不同，不能跨类型复用。

来源：[resources/yaml/subject_platforms.yml](../resources/yaml/subject_platforms.yml)
的 `define.types`（编码定义）与 `platforms`（中文名、别名、模板、排序配置）。

### 3.1 四套编码空间（不要混用）

| 编码空间 | 所在字段 | 作用 | 上文对应章节 |
|----------|----------|------|--------------|
| 作品（条目）类型 | `subject.type` | 1/2/3/4/6 | 第 1 节 |
| 关联关系类型 | `subject-relations.relation_type` | 描述作品之间的关系 | 第 2 节 |
| 平台 / 分类 | `subject.platform` | 同一 type 内的细分形态 | 本节 |
| 游戏硬件平台 | 游戏条目的平台字段 | PC/PS5/Switch 等 | 3.6 节 |

含义撞车的例子：`1` 在动画里是 TV，在三次元里是日剧，在书籍里没有定义；
`3001` 既是音乐关系“原声集”，又是音乐平台“专辑”。

## 4. 怎么区分这几类编号

1. **看数据文件名**：`type2_subject.jsonlines` 里的 `2` 是作品类型；
   `type2_subject-relations.jsonlines` 里的每一行是关系记录，其
   `relation_type` 才是上表 2.x 的编码。
2. **看字段位置**：`subject.platform` 是平台/分类（第 3 节）；`relation_type` 才是
   关系类型（第 2 节）。同一个四位数可能两边都存在（如 `3001`）。
3. **看含义**：关系类型描述「两部作品是什么关系」，不能单独归档成一份作品数据；
   平台编码描述「同一个 type 内的形态」，仍然属于作品数据的一列。

## 5. 流水线中的平台细分（type=1/2/6）

Rust 流水线已按平台把**同一个 xlsx 拆成多个工作表**（不是多个文件）：

| 环节 | 行为 |
|------|------|
| step05 合并 | 读取上期存档的**全部工作表**，避免只读第一个 sheet 而丢掉其他平台的历史数据 |
| step06 主存档 | 按 `subject.platform` 分组，每个平台一个 sheet，sheet 名用上表中文名；空值/未知值归入「其他」；`platform` 列会真实写入 |
| step07 模板 | 保留与主存档一致的 sheet 结构；同时把「类别」列从数字编码翻译成中文 |
| 覆盖范围 | type=1（书籍）、type=2（动画）、type=6（三次元）；type=3/4 仍保持单表 |
| 排序 | 按 yaml 中的 `order`；未在配置中的平台名按字典序追加 |

映射实现位于 `rust/bgm-pipeline/src/platforms.rs`，与
[subject_platforms.yml](../resources/yaml/subject_platforms.yml) 保持一致。
`4 短片` 已在 Rust 映射中支持；由于 yaml 的 `platforms` 段尚未配置该条目，
`broadcast_types` 仍只包含 TV/WEB/OVA/剧场版/动态漫画，不会把「短片」当成播出方式。

## 6. 流水线边界

- `ALL_TYPES = [1, 2, 3, 4, 6]`，流水线只按这五个作品类型拆分、对比、合并 Excel。
- 关系类型只作为 `subject-relations` 数据的字段参与清洗与导出，不会被当作类型
  进入 step01/03/04/05/06/07/09。
- 如果后续确实出现新的**作品类型**，按第 1.1 节的方式扩展；**不要**把 `3001`
  之类的关编码加入 `ALL_TYPES`，否则会去源数据里找不存在的 `type3001_subject`。
